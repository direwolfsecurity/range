@CA_NAME@

This is the range's own certificate authority, a pretend Let's Encrypt. Trust its root certificate once, and HTTPS works on every range site that uses it.

Check the fingerprint first. This page is plain HTTP, so anyone on the network could change it. The fingerprint below must match the one your teacher posted in the room. The scripts' quick check reads fingerprint.txt from this same server, so it can't catch that kind of tampering. The strict check can.

SHA-256: @FP@

Files

  • root_ca.crt: the root certificate (PEM text). Linux, Windows, Firefox.
  • root_ca.der: the same certificate in binary form. Android, some Windows tools.
  • root_ca.h: the same certificate as C code, for ESP32 and Pico W sketches.
  • install-root-linux.sh: installs it on Kali, Ubuntu and Debian.
  • Install-RangeRoot.ps1: installs it on Windows.

Kali, Ubuntu, Debian

curl -O http://@SERVER_NAME@/install-root-linux.sh
less install-root-linux.sh          # read a script before you run it as root
sudo bash install-root-linux.sh     # quick check against fingerprint.txt
# strict check, against the fingerprint posted in the room:
sudo bash install-root-linux.sh --fingerprint <posted fingerprint>

Windows (PowerShell as Administrator)

curl.exe -O http://@SERVER_NAME@/Install-RangeRoot.ps1
powershell -ExecutionPolicy Bypass -File .\Install-RangeRoot.ps1
# strict: add -Fingerprint <posted fingerprint>

Servers: get a certificate with ACME

sudo certbot certonly --standalone -d myserver.lab --server @ACME@

The server must trust the root first (step above), and its name must point to it in range DNS.
